# Player Helmet Lamps V1

> Одобрено пользователем 2026-07-31. Итерация 1 приземлена: два конусных
> источника, клавиша `L`, факел не тронут.

## Purpose

Заменить абстрактный носимый факел двумя фонарями, которые физически есть на
шлеме скафандра. Свет перестаёт быть безымянным тёплым кругом вокруг игрока и
начинает исходить из конкретного железа в конкретном направлении.

## Design Intent

Круглое пятно вокруг персонажа не говорит, куда он смотрит. Конус говорит.
Это меняет ощущение ночной вылазки: темнота перестаёт быть равномерной, у неё
появляется направление, а у игрока — необходимость повернуться, чтобы увидеть.

Фонарей два, потому что их два на модели, и они разные:

| Фонарь | Положение | Роль |
|---|---|---|
| Двухлинзовый блок | верх шлема, сдвиг вбок ≈ 0.083 роста | основной узкий конус вперёд, полуугол 21°, дальность ≈ 6.5 тайла |
| Одиночный боковой | противоположная сторона, сдвиг ≈ 0.064 роста | широкий подсвет, полуугол 44°, отвёрнут на 34°, дальность ≈ 3.5 тайла |

Дальность задаётся в тайлах (64 px), а не подбирается на глаз. Первая проба
шла с лучом на 10 тайлов: конус занимал пол-экрана и подавлял сцену вместо
того, чтобы её раскрывать.

Голова стоит на 86% роста (замерено на `Standing Idle.fbx`: голова `z = 0.817`
при росте `0.948`). В игровом масштабе фигура занимает около 56 px, поэтому
боковой разнос ламп — единицы пикселей, и в V1 смещения заданы константами в
экранных пикселях, а не запекаются покадрово.

## How The Light Is Built

Свет **не** является маской персонажа. В Godot 2D источник — это `PointLight2D`,
у которого текстура задаёт форму светового пятна; существующий `PlayerTorch`
уже работает так, генерируя радиальную текстуру процедурно.

V1 меняет три вещи и не изобретает новый механизм:
- форма текстуры — конус с мягкими краями вместо круга;
- количество узлов — два вместо одного;
- поворот — узлы поворачиваются по текущему `_visual_direction` (16 шагов).

Маска нужна для **другого** и здесь обязательна: чтобы сами линзы светились на
спрайте, когда фонарь включён. Без неё ночью фонарь освещает мир, но лампа на
шлеме выглядит выключенной. Это отдельный маленький emissive-канал в бейке,
где белым помечены только линзы.

Точки крепления света печутся в метаданные бейка **на каждый кадр и каждое
направление**, тем же способом, что и контактная линия ног в
`player_visual_presentation_v1.md`. Причина: при повороте и в анимации голова
двигается, и фиксированное смещение отвязало бы конус от железа.

## ADR-0005 Boundary (non-negotiable)

[ADR-0005](../../05_adrs/0005-light-is-gameplay-system.md): свет — геймплейная
система, каждый источник обязан иметь цену на питание или топливо, а геймплей
читает авторитет видимости, а не рендерер.

V1 строит **только визуальную половину**, ровно по тому прецеденту, который уже
задокументирован в `player_torch.gd`: свет визуальный сейчас, батарея позже.
Это должно быть записано явно, иначе результатом станет бесплатный вечный свет,
разрушающий контраст «внутри безопасно — снаружи опасно».

V1 не создаёт и не подменяет авторитет видимости. Ни одна геймплейная система не
получает права читать эти узлы.

## Torch Replacement — Not A Deletion

Пользователь разрешил выпилить факел, «если это норм заработает». Прямое удаление
невозможно: `PlayerTorch` несущий. От него зависят:

| Зависимость | Что читает |
|---|---|
| `core/systems/world/mountain_torch_shadow_field.gd:97` | константу `PlayerTorch.ENERGY` |
| `core/systems/world/mountain_torch_shadow_field.gd:106` | узел `"Torch"` под игроком |
| `tools/mountain_torch_occluder_shape_smoke_test.gd` | исходник скрипта |
| `tools/mountain_torch_shadow_field_static_smoke_test.gd` | исходник скрипта |
| `tools/mountain_torch_shadow_field_live_perf_probe.gd` | узел `"Torch"` |
| `tools/ground_light_probe.gd`, `tools/ground_rock_islet_probe.gd` | узел `"Torch"` |
| `docs/02_system_specs/world/world_dynamic_lighting_2d.md` | владеет контрактом факела |
| `docs/02_system_specs/world/mountain_cavity_skylight_occlusion.md` | ссылается на факел |

Поэтому замена делается **миграцией контракта**, а не удалением файла: остаётся
единственный источник, на который смотрит `MountainTorchShadowField`, и меняется
его форма, количество и клавиша. Открытый вопрос итерации 2 — как поле горных
теней трактует два конуса вместо одного круга: берёт основной фонарь как
единственный вход или суммирует. Решается пробой, не догадкой.

Удаление `player_torch.gd` разрешено **только** после того, как все перечисленные
зависимости переведены и их тесты проходят.

## Input

| | старое | новое |
|---|---|---|
| Клавиша | `KEY_F` | `KEY_L` |
| Поведение | toggle, выключен по умолчанию | toggle, выключен по умолчанию |

Клавиша объявляется через существующий input-путь проекта, а не хардкодом
keycode, если это не ломает нынешний dev-toggle прецедент.

## Runtime Classification

| Вопрос | Ответ |
|---|---|
| Runtime class | interactive-frame presentation |
| Authoritative data | нет; visual-only |
| Single write owner | `PlayerHelmetLamps` владеет только своими двумя узлами света |
| Save/load impact | нет в V1; появится вместе с батареей |
| Determinism impact | нет |
| Dirty unit | два локальных `PointLight2D` (поворот, вкл/выкл) |
| Target scale | один локальный игрок; co-op повторяет O(1) на видимого игрока |
| Escalation path | текстуры конусов кэшируются статически и переиспользуются |

## Runtime Rules

- Обе текстуры конусов создаются один раз и кэшируются статически, как это уже
  делает `PlayerTorch._make_radial`.
- Поворот света обновляется только при смене `_visual_direction`, а не каждый кадр.
- Узлы света не включают engine shadow maps; перекрытие горой остаётся за
  `MountainTorchShadowField`.
- Ни один геймплейный путь не читает эти узлы для видимости.

## Iterations

- **I1** — два конусных источника рядом с существующим факелом, клавиша `L`.
  Факел остаётся на месте и не трогается. Приёмка: свет идёт из шлема и
  поворачивается вместе с персонажем.
- **I1b** — emissive-свечение линз. Вынесено из I1 отдельным шагом: запекать
  маску по пикселям на 1280 кадров дорого, а дешёвый путь — записать в
  метаданные бейка экранную позицию каждой линзы по кадрам и рисовать в ней
  аддитивную точку. Без этого фонарь ночью освещает мир, но сама лампа на
  спрайте выглядит выключенной.
- **I2** — миграция `MountainTorchShadowField` и пяти проб на новый источник,
  затем удаление `player_torch.gd` и обновление двух world-спек.
