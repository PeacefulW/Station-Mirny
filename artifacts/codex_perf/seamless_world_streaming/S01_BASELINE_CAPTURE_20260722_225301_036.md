# S1 baseline capture `20260722_225301_036`

## Вердикт

Маршрут `S1-MOUNTAIN-SOUTH-01` воспроизведен и прошел offline validator.
Baseline не выполняет общую seamless/60 FPS цель: крупные черные области
видны во всех 13 ручных event screenshots, а чистый zoom-0.2 участок дает
`50.561 FPS`, P95 `24.313 ms` и GPU P95 `23.183 ms`.

Этот документ фиксирует исходное плохое состояние; он не является заявлением,
что streaming исправлен. S1 еще требует короткий night/cave/torch visual pass
и явное подтверждение пользователя.

Recorder V0 не пишет memory columns в trace, поэтому память фиксируется по
пользовательским F2 screenshots:

| Момент | VRAM | RAM |
|---|---:|---:|
| Первый manual event, 12 s | `1.3 GiB` | `273.6 MiB` |
| Максимум, увиденный в event screenshots | `1.6 GiB` | `418.8 MiB` |
| Последний event, 119 s | `1.6 GiB` | `407.1 MiB` |
| Post-run F2, примерно +5 s | `1.6 GiB` | `393.8 MiB` |

За один двухминутный прогон VRAM вырос примерно на `0.3 GiB`, RAM достигла
`+145.2 MiB` относительно первого manual кадра. Этого недостаточно, чтобы
делать вывод об утечке; для S8 потребуется длинный plateau/return test.

## Visual baseline

Все 13 ручных screenshots внутри F4 показывают player-visible черные
прямоугольники незагруженной presentation на zoom `0.2`. Дефект встречается у
краев и внутри viewport, во время движения, при `visibility_wait 25..51`.
Представительные кадры:

- `events/0001_manual.png` — probe identity, dense objects и черные области
- `events/0005_queue_pressure.png` — крупные отсутствующие прямоугольники
- `events/0007_manual.png` — несколько дыр внутри viewport при движении
- `events/0015_manual.png` — дефект сохраняется у конца маршрута
- post-run `snapshot.png` — дефект остается после остановки recorder

Day/plains/dense objects и mountain edge зафиксированы. Night, отдельный
mountain close-up и cave/torch on/off в этом прогоне отсутствуют.
